# ระบบสั่งอาหาร Thaidrill LAO

เว็บแอปบันทึกจำนวนอาหารรายวัน สร้างตามโครงสร้างแบบฟอร์มในเอกสาร “แจ้งจำนวนสั่งอาหาร โครงการเซโปน 2026” โดยแยกมื้อเช้า เที่ยง เย็น ดึก และมื้อไม่ปกติ รวมทั้งแยกกินที่โรงครัว ข้าวเหนียวห่อ และข้าวจ้าวห่อ

## เริ่มใช้งาน

```bash
npm install
npm run dev
```

เปิด URL ที่แสดงใน Terminal โดยข้อมูลจะบันทึกในเบราว์เซอร์ของเครื่องที่ใช้งาน (Local Storage)

## บัญชีเข้าใช้งาน

เข้าสู่ระบบด้วย LID และรหัสส่วนตัวเท่านั้น (บัญชีแผนกที่ใช้รหัสร่วมกันเลิกใช้แล้ว
เพราะระบุไม่ได้ว่าใครเป็นคนกดส่ง) แผนกของผู้ใช้มาจากโปรไฟล์ในตาราง `app_users`

บัญชี Admin โรงครัว — เห็นยอดสรุปจากทุกแผนก จัดการ User และสถานที่ส่งได้:

| โครงการ | LID | รหัส |
| --- | --- | --- |
| เซโปน | 8000001 | 9999 |
| เซกอง | 8000002 | 9999 |

บัญชี Demo สำหรับทดสอบ (เก็บในเครื่อง ไม่ต้องต่อฐานข้อมูล):

| สิทธิ์ | LID | รหัส | แผนก |
| --- | --- | --- | --- |
| ผู้ใช้ เซโปน | 9000001 | 1234 | IT |
| ผู้ใช้ เซกอง | 9000002 | 1234 | IT |
| Admin โรงครัว | 9000000 | 9000 | Canteen |

ผู้ใช้ทั่วไปจะเห็นและแก้ไขได้เฉพาะรายการของแผนกตัวเอง ส่วน Admin โรงครัวจะเห็นยอดสรุปจากทุกแผนก และสลับดูได้ทั้งสองโครงการ

## ความสามารถ

- แยกรายการตามแผนกและทีมงาน
- คำนวณยอดข้าวห่อ ยอดแต่ละมื้อ และยอดรวมอัตโนมัติ
- เลือกวันที่ ค้นหา และกรองแผนก
- เพิ่ม แก้ไข และลบทีมงาน
- บันทึกข้อมูลในเครื่อง พร้อมป๊อปอัปยืนยัน
- สถานะ แบบร่าง / ยืนยันแล้ว / ส่งโรงครัวแล้ว
- ส่งออก CSV และพิมพ์รายงานแนวนอน
- หน้า Login ด้วย LID ส่วนตัว แยกสิทธิ์ผู้ใช้ทั่วไปกับ Admin
- หน้า Admin โรงครัวสรุปยอดรายมื้อและประเภทข้าวจากทุกแผนก

> รายการสั่งอาหารยังเก็บใน Local Storage ส่วนข้อมูลพนักงานและบัญชี User เชื่อมผ่าน Google Sheets ตามขั้นตอนด้านล่าง

## เชื่อมระบบสมัคร User กับ Google Sheets

1. นำไฟล์ `Code.gs` ฉบับปรับปรุงไปวางใน Apps Script ที่ผูกกับ Spreadsheet
2. Deploy เป็น Web app โดยตั้ง Execute as เป็นเจ้าของไฟล์ และอนุญาตผู้ใช้งานที่ต้องเข้าเว็บ
3. เข้า Admin โรงครัว > User แล้วกรอก Web App URL
4. กด “ดึงข้อมูลพนักงาน” เพื่อตรวจการเชื่อมต่อ

หน้าสมัครบัญชีมี 3 ช่องเท่านั้น: ผู้ใช้ (LID), รหัสเข้าใช้งาน และยืนยันรหัส — ไม่ต้องค้นหาพนักงานจากชีต `DataForScan` ก่อน ถ้า LID นั้นมีอยู่ในตาราง `employees` ฐานข้อมูลจะเติม MR-MRS, FirstName, LastName, position, department, location และ company ให้อัตโนมัติ ถ้าไม่มีก็สมัครได้ตามปกติแต่ช่องเหล่านั้นจะว่าง จากนั้นระบบจะแยกบันทึกดังนี้:

- location เซโปน บันทึกลงชีต `UserXEPON`
- location เซกอง / Xekong / Sekong บันทึกลงชีต `UserXEKONG`

หากยังไม่มีชีตผู้ใช้ ระบบจะสร้างหัวตารางให้อัตโนมัติ รหัสผ่านจะถูกบันทึกเป็นค่า SHA-256 ไม่เก็บข้อความรหัสผ่านโดยตรง หน้า Login ของผู้ใช้งาน LID จะตรวจบัญชีกับสองชีตผ่าน Web App API

สำหรับการติดตั้งแบบกำหนด URL ตอน Build สามารถสร้างไฟล์ `.env` แล้วตั้งค่า:

```env
VITE_GOOGLE_SCRIPT_URL=https://script.google.com/macros/s/DEPLOYMENT_ID/exec
```

## เชื่อมฐานข้อมูล Supabase

ตั้งค่าไฟล์ `.env`:

```env
VITE_SUPABASE_URL=https://PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

โปรเจกต์ใหม่ให้เปิด Supabase SQL Editor แล้วรันไฟล์ในโฟลเดอร์ `supabase` ตามลำดับ `01` ถึง `13`

หากฐานข้อมูลเดิมรันไฟล์ `01`–`10` แล้ว ให้รันเฉพาะ:

```text
supabase/11_delivery_points.sql
supabase/12_app_users_free_lid.sql
supabase/13_kitchen_admin_users.sql
```

`11` สร้างตาราง `delivery_points` แยกตามโครงการ พร้อมรายการเริ่มต้น และฟังก์ชันเพิ่ม แก้ไข ลบที่ตรวจ PIN แอดมินจาก `app_config` ฝั่งฐานข้อมูล ผู้ใช้ทั่วไปอ่านรายการเพื่อเลือก “ส่งห่อที่” ได้ แต่เขียนลงตารางโดยตรงไม่ได้

`12` ถอด foreign key `app_users.lid → employees.lid` ที่ค้างจากไฟล์ `04` ออก เพราะไฟล์ `10` เปลี่ยนกติกาไปแล้วว่า LID ที่ไม่มีในชีต `dataforscan1` ก็สมัครได้ ถ้าไม่ถอด การสมัครแบบใหม่จะล้มด้วย error `23503`

`13` สร้างบัญชี Admin โรงครัวประจำโครงการไว้ในฐานข้อมูล เข้าใช้ที่แท็บ “ผู้ใช้งาน LID”:

| LID | โครงการ | รหัสเริ่มต้น |
| --- | --- | --- |
| `8000001` | เซโปน | `9999` |
| `8000002` | เซกอง | `9999` |

ต่างจากบัญชีทดลอง LID `9000000` ที่เก็บใน localStorage ของเครื่องเดียว — บัญชีชุดนี้อยู่ในฐานข้อมูล เข้าได้จากทุกเครื่อง และติดชื่อผู้บันทึกไปกับออเดอร์ เปลี่ยนรหัสภายหลังได้ด้วย `reset_user_pin(lid, รหัสใหม่, admin_pin)`
